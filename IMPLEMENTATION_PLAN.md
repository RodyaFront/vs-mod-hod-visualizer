# План реализации HOD Visualizer

## Цель
Сделать отдельный мод-визуализатор, который отображает ключевые статусы `HydrateOrDiedrate` через систему `PlayerStatusStrip`, без вмешательства в логику оригинального мода.

## Зафиксированный набор статусов (по требованиям)
- `Жажда` как пороговые статусы (не постоянный %):
  - `> 50%`: статус не показывается.
  - `20-50%`: статус `Жажда`.
  - `< 20%`: статус `Сильная жажда`.
  - `0%`: критический статус `Вы умираете от дегидрации` (технически в HoD значение не уходит ниже 0).
- `Охлаждение/Жара`:
  - отдельные иконки `Вам жарко` / `Вам холодно`;
  - tooltip должен объяснять влияние на жажду в формате "Потеря очков жажды увеличена на X% (из-за жары)".
- `Перегруз жидкостями`:
  - обязательный статус высокого приоритета;
  - должен явно объяснять причину замедления.
- `(Опционально) Штраф пит. веществ`:
  - пример названия: `Вода была с привкусом`;
  - в tooltip выводить текущее накопленное значение штрафа (`nutritionDeficitAmount`).

## Этап 1. Базовый каркас мода
- Создать структуру VS-мода:
  - `modinfo.json`
  - `.csproj`
  - `src/HodVisualizerModSystem.cs`
- Задать `modid` и версию `0.1.0`.
- Подключить ссылки на `VintagestoryAPI`, `VSSurvivalMod` и библиотеку `PlayerStatusStrip` (по принятому в workspace способу).

## Этап 2. Интеграция с PlayerStatusStrip
- Добавить отдельный провайдер/регистратор статусов для HoD.
- На клиенте зарегистрировать статусы в момент старта мода.
- Обеспечить безопасный fallback:
  - если `hydrateordiedrate` не установлен;
  - если нужные `EntityBehavior` отключены конфигом HoD;
  - если игрок еще не инициализирован.

## Этап 3. Минимальный набор статусов (MVP)
- Реализовать 3 пользовательских статуса:
  1. `Жажда` (пороговая логика по % текущей жажды)
  2. `Вам жарко/Вам холодно` (по знаку и величине охлаждения)
  3. `Перегруз жидкостями` (объяснение замедления)
- Источники:
  - `EntityBehaviorThirst` (`WatchedAttributes["thirst"]`)
  - `WatchedAttributes["hodCooling"]`
  - `entity.Stats`/инвентарь для определения encumbrance-состояния
- Обновление значений сделать легковесным, без частых аллокаций.

## Этап 4. Расширенные статусы
- Добавить опциональный статус `Вода была с привкусом`:
  - показывать при `nutritionDeficitAmount > 0`;
  - в tooltip выводить текущее значение штрафа.
- Добавить расширенные tooltip для жажды:
  - текущий tier;
  - точка следующего перехода.
- Добавить расширенные tooltip для температуры:
  - итоговый эффект в % на расход жажды относительно базы.

## Этап 5. UX и формат отображения
- Согласовать короткие подписи и формат:
  - проценты;
  - округление float;
  - понятные формулировки причины дебаффа.
- Добавить локализацию строк (`assets/.../lang/en.json`, `ru.json`).
- Определить цвет/иконку/приоритет отображения под стиль `PlayerStatusStrip`.

## Этап 6. Конфиг визуализатора
- Добавить конфиг нового мода:
  - включение/отключение каждого статуса;
  - период обновления;
  - компактный или подробный режим.
- Реализовать безопасные дефолты при отсутствии файла конфигурации.

## Этап 7. Тестирование
- Проверить сценарии:
  - HoD включен/выключен;
  - thirst включен/выключен;
  - harsh heat включен/выключен;
  - жажда в каждом диапазоне (50%+, 20-50%, <20%, 0%);
  - наличие/отсутствие encumbrance;
  - наличие/отсутствие nutrition deficit;
  - одиночная игра и сервер.
- Прогнать smoke-тест на отсутствие ошибок в логах клиента.
- Проверить, что визуализатор не ломает FPS и не спамит аллокациями.

## Этап 8. Подготовка к первому релизу
- Обновить `CHANGELOG.md` нового репозитория.
- Подготовить минимальный README:
  - что показывает мод;
  - зависимости (`HydrateOrDiedrate`, `PlayerStatusStrip`);
  - установка.
- Сформировать первый релизный архив и проверить установку в тестовый `Mods`.
